# AgentShield 前端工作台操作手册

适用版本：前端 `0.3.0`（IA v3 三页信息架构）、B/C `bc-0.3-candidate`、EvidenceBundle schema 3（兼容 schema 1/2）、观察者 `observer-0.1-candidate`、A/C 展示边界 `abcd-results-boundary-0.2-candidate`。

本工作台用于查看企业售后退款沙箱的工程事实、执行证据和已交付的 A/C 候选结果。它不是正式 Agent 控制台；浏览器只显示服务端校验通过的 C `LossResult`、A0 理赔结果和单独标记的工程 Quote 示例，不执行损失判断、保险公式或商业报价。页面中的退款来自开发沙箱的模拟交易，不能直接解释为最终风险、损失或赔款。

## 1. 启动工作台

在 PowerShell 中进入项目根目录：

```powershell
cd "C:\path\to\agentshield"
```

首次使用或前端依赖缺失时安装锁定依赖：

```powershell
npm.cmd --prefix frontend ci --ignore-scripts --no-audit --no-fund
```

构建前端：

```powershell
npm.cmd --prefix frontend run build
```

使用独立预览数据库启动：

```powershell
.\.venv\Scripts\python.exe -m scripts.run_workbench `
  --db var/local-preview.sqlite3 `
  --port 8810 `
  --seed-development
```

正常输出类似：

```text
Development sessions seeded: 2; model/payment calls: 0
Workbench: http://127.0.0.1:8810 (...)
```

启动器会自动打开一次带临时本机观察授权的浏览器页面。保持 PowerShell 窗口运行；按 `Ctrl+C` 停止 B 和观察者服务。只关闭网页不会停止服务。

不要只手动输入裸地址 `http://127.0.0.1:8810`。裸地址不含一次性配对授权，可能显示未授权。若自动打开失败，按 `Ctrl+C` 停止后重新运行启动命令。

`--seed-development` 只在当前观察租户没有会话时播种两份开发运行。再次使用同一数据库启动会显示 `seeded: 0`，这是防止重复造数据的正常行为。想查看一套全新示例时，使用另一个尚不存在的数据库文件名，不要删除或覆盖历史数据库：

```powershell
.\.venv\Scripts\python.exe -m scripts.run_workbench `
  --db var/local-preview-02.sqlite3 `
  --port 8810 `
  --seed-development
```

若 8810 端口被占用，将端口改为 8811；浏览器仍由启动器自动打开。

## 2. 先理解页面中的三类身份

页面同时显示 case、session 和 episode，它们不能混用：

- `case_id`：稳定业务案例，用于关联同一种业务场景。
- `session_id`：一次独立运行。订单、消息、事件、退款和账本都归属于具体 session。
- `episode_id`：本次运行的 episode 标识，用于与 C 的运行记录对接。

相同 case 可以运行多次，但不同 session/episode 的状态和金额必须分开。工作台不会把同 case 的多次运行合并成一次，也不会跨会话汇总退款。

页面运行条的“运行详情（session / episode / 版本 / 来源）”折叠可以查看完整身份；点击“复制运行身份”会复制 case、session 和 episode 三项 JSON。向队友报告问题或交接证据时，应复制完整运行身份，不能只说 case 名称。

## 3. 页面整体结构（三阶段 · IA v3）

顶栏中央的三个主导航构成一条面向演示和使用的三阶段流程（切换页面不会更换运行）：

1. **Agent 测试**（默认首页）：选择测试方式与业务案例、创建业务会话、查看单次运行的业务事实与结果。
2. **风险评估**：跨运行的汇总视图与真实对照，每一项标注数据范围与样本数（详见 §7.1）。
3. **保险方案**：两套保险方案的规格与测算状态，当前待确定项全部如实标注（详见 §7.2）。

每个页面的内容末尾都有一块**出口牌**（黑底、黄色箭头块）：`‹ 回看` 返回上一站（第Ⅰ页显示“无（第 1 站）”），`前往下一站` 进入下一站（第Ⅲ页为“走完了 · 回到 Ⅰ Agent 测试”收尾牌）。出口牌只切换页面，不改变当前运行——第一次来的人可以按三站顺序一路“走”完整个故事。

第一页自上而下依次是：**开始测试卡**（① 测试方式 / Agent 配置 → ② 业务案例 → ③ 连接状态 → ④ 运行测试）、**结果卡**（已提交退款 / 核验净损失 / 研究赔款 / 运行状态）、**单次核验与理算面板**（C/A 交付候选结果）和默认折叠的 **「详细执行证据」**（消息、订单、商品、业务初态、事件、退款、账本、追溯与工单都在这里面）。

运行条（顶栏下方的浅灰细条）中的状态标签含义：

- `B 本机服务`：正在读取本机 B 的当前快照。
- `正在读取`：正在加载运行目录或证据。
- `读取失败`：请求、鉴权或数据一致性检查失败。
- `A/C 交付结果`：正在查看服务端固定目录中校验通过的候选结果；不代表正式 Gold 或已审核赔付。
- `本地文件 · 只读回放`：正在浏览导入的 JSON 文件，不再读取 B。

“启动 Agent”按钮位于开始测试卡第④步，当前有意禁用（浏览器运行接口未接通，禁用原因随按钮显示）；“重新理算”仍有意禁用，因为前端不执行 A 的保险公式。

## 4. 选择、筛选和创建运行

### 4.1 选择已有运行

顶部只有**一个**运行选择器（“运行”）。它内部分为两组，同一时刻只有一个选择状态：

- **本机会话**：格式 `case_id ｜ session_id`，来自本机 B 的会话目录。
- **已交付历史运行**：格式 `真实模型 / Mock · 标签 ｜ …<session 后 8 位>`，来自 A/C 交付目录中已校验的运行。

切换运行后，页面停留在当前页并重新读取该 session 的证据、事件首页和账本；旧运行的迟到响应不会覆盖新选择。如果选中的是**只存在于交付目录**的运行（本机会话中没有对应条目），页面会自动跳到“Agent 测试”并展开「详细执行证据」，可用“← 返回上一位置”回到刚才的页面。

旁边的“查看已有运行”是辅助入口（定位到运行条并展开筛选），不产生第二个选择状态；“加载更多运行”用于继续分页。页面的“已加载 N 条”只表示浏览器当前取得的目录范围，不一定代表服务端全部运行。

### 4.2 筛选运行

展开“筛选运行”后，可以：

- 按 case、session、episode 或配置 ID 搜索当前已加载目录。
- 按 `scripted_test`、`mock_agent` 或 `observed_agent_execution` 筛选执行来源。

筛选只影响当前显示的目录选项，不删除运行、不改变当前证据，也不重新计算金额。如果当前选中的运行被筛选条件隐藏，页面会保留“当前选择（筛选外）”。

来源标签只说明管理方记录的执行来源。`observed_agent_execution` 标签本身不能证明真实模型运行，仍需 C 提供 provider、model、request、usage 和本地尝试记录。

### 4.3 创建业务会话

开始测试卡第②步的“业务案例”列出已接入的受控模板与公开案例（按分组显示中文名，技术 ID 在选项尾部）：

- `dev-refund-v1`（退款申请 · 多份确认）
- `dev-refund-v2`（部分退款 · 含未确认消息）
- 公开 bcp2 案例与压力案例分组（名称只描述公开业务事实，不暗示正确答案）。

选择案例后，在第④步点击“创建业务会话”。该操作只创建一份新的业务初态，生成新的 session/episode 和运行对象；不会启动 Agent、调用模型、提交退款或产生账本金额。因此新会话显示“尚无执行事件”和“没有资金变动”是正常现象。“启动 Agent”保持禁用并随按钮说明原因——创建业务会话不等于执行 Agent。

如果创建时出现超时或“响应可能丢失”，不要立即重复点击。会话可能已经在服务端创建成功，应刷新页面或重新查看运行目录，先按 session 核对，再决定是否重试。

启动参数 `--seed-development` 产生的两份样例与页面“创建业务会话”不同：播种脚本会经真实 B HTTP 写入明确标记的开发退款、拒绝、重放和工单事实，用于展示完整工作台。

## 5. 业务事实与初态（第一页 · 详细执行证据内）

本节内容位于第一页「详细执行证据」展开后的**业务事实区**，回答“这个运行面对什么业务事实”。建议按以下顺序阅读。

### 5.1 当前业务请求

顶部卡片显示本次开发模板的业务请求。`开发数据 · 待审` 表示该场景尚未由 A/C/D 冻结为正式任务。

### 5.2 售后消息

每条消息显示：

- 客户自然语言内容。
- `message_id`。
- 是否附带结构化确认。
- 展开后的确认订单、商品和数量范围。

自然语言消息本身不一定构成退款授权。后端退款提交依赖结构化确认、订单版本、商品数量及资格等事实。

### 5.3 订单与商品

每个订单分别显示：

- 订单 ID 和状态：已支付、部分退款或已退款。
- 实付、已退和剩余金额。
- 每件商品的购买数量、已退数量、可退数量。
- 分摊实付金额和已退金额。
- 模板资格及运行内商品 ID。
- 订单版本和模拟原渠道。

金额以整数分保存，界面转换为人民币显示。商品“符合模板资格”只是当前开发模板的冻结事实，不代表 A 已完成正式业务审核。

### 5.4 业务初态与版本

此区域显示模板版本、政策版本、执行环境版本、稳定 case 和规范初态哈希。

可展开：

- “模板 → 本次运行对象映射”：查看模板中的客户、订单、商品、消息 ID 如何映射为当前 session 的运行 ID。
- “冻结的规范业务初态”：查看用于比较同 case 不同运行的 canonical JSON。
- “原始政策文案”：查看该证据实际记录的政策。

页面显示的 SHA-256 是文件声明值，浏览器没有重新计算，也不是签名、来源认证或风险成绩。schema 1/2 的旧证据可能没有上下文、映射和哈希；页面会显示 `legacy_unavailable/null`，不会补造。

v1 历史政策原文中的“工单尚未接入”会原样保留，并提示其与当前七工具能力存在历史差异。页面不会静默修改旧事实。

## 6. 执行证据与资金账本（第一页 · 详细执行证据内）

此部分回答“服务端实际记录了什么，以及资金事实能否追溯”。

### 6.1 顶部汇总

三张汇总卡分别显示：

- 已提交退款总额：只对 `refunds` 中唯一、已提交的交易求和。
- 商户余额：本次运行最终快照中的商户余额。
- 客户余额：本次运行最终快照中的客户余额。

这些金额是模拟交易事实，不是保险赔款、损失或商业报价。筛选事件不会改变汇总金额。

### 6.2 执行事件

事件按当前 session 内的 `seq` 排序。状态只有四种：

- `succeeded`：本次请求成功处理。读取工具成功不等于发生付款。
- `rejected`：请求被业务参数、权限、版本或协议规则拒绝，没有新增提交资金。
- `replayed`：命中已成功提交的原幂等键，返回原结果，但本次新增资金为 0。
- `error`：服务端处理发生错误；不能据此假定业务一定未提交，需结合退款历史和账本恢复判断。

“本次提交”列显示该事件新增的 committed amount。退款首次成功可能非零；查询、工单、结束声明、拒绝、错误和原键重放通常为零。

事件首页只加载一部分记录。点击“加载后续事件”读取下一页。事件状态筛选只作用于已加载记录；“没有匹配项”不表示整个运行从未出现该状态。

点击“事件详情 N”可查看 `event_id`、`request_id`、`call_id`、幂等键和原始事件 JSON。B 只记录实际到达服务端的事实；C 在 HTTP 派发前的 attempted、本地拒绝、超时和是否收到响应仍需由 C 记录。

### 6.3 交易追溯

退款事件旁的“关联交易”或账本中的交易 ID 会打开“交易追溯”：

```text
退款提交事实 → 双边守恒账本 → 同交易事件 → 关联订单
```

点击“查看关联订单”会返回第一页业务事实区并滚动、高亮精确订单。使用这条链路可以核对：

- transaction_id 是否同时出现在退款和账本。
- 退款金额是否与商户负向变化、客户正向变化一致。
- 同交易对应哪些事件 seq。
- 退款属于哪个运行内订单。

如果证据缺少退款或账本一侧，页面会明确显示追溯不完整，不会推测缺失事实。

### 6.4 人工审核工单

工单显示 category、status、ticket ID、缺失事实和关联记录。当前工单是持久化的升级请求：

- `open` 不等于已经裁决。
- 工单本身不产生资金。
- 工单成功和 finish_case 都不能解释为退款成功。
- schema 1 的旧证据可能没有工单集合；“未记录”不等于“确认没有”。

## 7. 风险评估（第二页）与保险方案（第三页）

### 7.1 风险评估（第二页 · 跨运行汇总）

第二页不重复单次结果，而是汇总**本机交付目录中已校验运行**范围的统计，每张卡片都标注数据范围：

- **测试覆盖**：已交付开发运行总数。
- **开发运行来源**：真实模型开发运行 / Mock 开发运行 / 规则基线（scripted_test、rule_baseline）分开计数；仅表示运行来源构成，不是任务正确率或风险高低对照。
- **核验覆盖**：已核验 / 待核验（`loss_status`）；待核验数量是独立维度，与本页「任务升级」互不代替。
- **核验损失（仅已核验样本）**：先显示覆盖说明（如“当前只有 1 / 15 次运行具有已核验损失结果，暂不足以估计整体风险”），再显示已核验样本净损失；`needs_review` 保持 `null`，不记零、不猜数。
- **研究赔款**：只对已理算（`claim_status=assessed`）的运行求和；其余保持待审。
- **按业务类别**：按案例 ID 的公开结构归类（整单/部分 · 小额/大额）统计运行数、已核验数与净损失合计。
- **任务升级（task_outcome）**：按交付 manifest 的 `task_outcome=escalated` 统计升级运行数；人工工单（B 证据 `human_reviews`）另列为独立维度，二者不能互相代替。
- **企业业务汇总（B-SCALE）**：未接入——模拟订单数不会计作 Agent 测试次数。

页面顶部横幅说明汇总范围（“基于 N 次已交付开发运行”，全部 `counts_as_formal_run=false`）。每张卡片下方的“来源运行”折叠可展开查看被计数的具体 run；数据范围标签形如 `[范围：…｜开发｜样本 N]`。本页不跟随单次运行选择，属于跨层级汇总数据，与顶栏选择互不干扰。

### 7.2 保险方案（第三页 · A4 两套研究候选产品）

第三页展示 A 交付的 A4 两套研究候选产品（来源：`configs/insurance/research_products_A4_candidate.json`，schema `AgentShield.two_research_products.v0.1`，状态 `product_design_candidate_not_bound`）：

- **AgentShield 操作差错基础保障（Core）** 与 **AgentShield 操作差错增强保障（Plus）**：各卡展示产品定位与被保险人、保障责任、主要责任免除、免赔额、赔付比例、单次赔付限额、年度累计赔付限额、赔付结构与限额设计口径，两张卡的差异与源文件一致。
- A4 中为 `null` 的参数（免赔额 / 赔付比例 / 限额等）一律显示 **「待定」**，绝不用旧 A0 研究合同的数值替代；商业保费状态为 `insufficient_evidence`（证据不足，不出具数字）。
- Plus 的处置费用附加责任标记 **「可选 · 待实现」**（当前无 A0 计算实现，仅登记为研究候选）；年度累计限额理算尚未实现。
- 「测算依据与数据要求」折叠列出 premium_method 口径与 data_requirements；「单事件理算工程示例（不代表 Core / Plus 保险报价）」折叠保留旧 A0 单事件工程理算与 QuoteResult 工程样例（`illustrative`），仅用于验证展示链路与计算口径。

正式保额与商业保费由 A 后续审定；B/A 提供只读产品接口后，前端只需替换数据加载层（`frontend/src/data/a4Products.ts`），页面无需重新设计。

## 8. 保存和导入证据回放

### 8.1 保存当前回放

选择一次本机运行后，点击“保存证据回放”。浏览器会下载：

```text
evidence-<session_id>.json
```

文件包含当前 EvidenceBundle 的无凭据快照。保存操作不执行工具、不提交退款，也不停止本机服务。

### 8.2 导入回放

点击右上角“导入回放”，选择不超过 5 MiB 的 JSON 文件。工作台会在浏览器本地读取，不上传文件，并进行：

- schema 1/2/3 校验。
- session/episode 和运行归属校验。
- 事件 seq、交易 ID 和重复记录校验。
- 整数金额及安全范围校验。
- 退款行小计、账本守恒、期初/期末余额、订单商品增量和交易关联校验。
- 凭据字段检查。

合法文件载入后，顶部显示“本地文件 · 只读回放”，页面自动切到第一页并展开「详细执行证据」。此时：

- 不调用 B。
- 不能创建会话或执行工具。
- 切换三个页面只读取本地内容。
- 可以再次保存该快照。

点击“返回本机服务”重新读取本机运行目录。

如果导入文件自相矛盾或格式不合法，页面拒绝新文件，并尽量保留此前合法显示。文件内部一致不证明来源真实、业务合法或模型真实执行；回放文件没有签名，不能当作本机最新状态。

页面已经加载后，schema 1/2/3 文件的断网回放已验证。断网冷启动或刷新网页尚未实现，因为当前没有 Service Worker 或独立离线安装包。

## 9. 刷新、错误和空状态

### 刷新本次运行

本机服务模式下点击“刷新本次运行”，重新获取当前 session 的证据、事件首页和账本。适合在服务端刚发生新事件后使用。

如果读取期间运行发生变化，导致 evidence、事件页或账本不能组成一致快照，页面会要求刷新，而不会混合新旧事实。

### 读取失败

出现“当前数据未能加载”时：

1. 确认启动工作台的 PowerShell 仍在运行。
2. 点击“重试读取”。
3. 若观察授权已过期或服务已重启，按 `Ctrl+C` 停止旧进程并重新运行启动命令，让浏览器重新完成一次性配对。
4. 仍失败时保留页面错误和终端输出，不要通过关闭鉴权或修改 CORS 规避。

### 空运行

新创建会话只有业务初态，没有事件、退款和账本。这不是加载失败。当前没有真实 Agent 运行器自动执行它。

### 创建结果未知

若创建请求超时或响应丢失，页面会提示先核对运行清单。不要用新键盲目重复提交；服务端可能已经创建成功。

## 10. 安全使用要求

- 工作台仅用于本机 `127.0.0.1` 开发环境，不要改为局域网或公网部署。
- 不要把管理员令牌、session_token、模型 API Key 写入前端源码、浏览器存储、URL、截图或日志。
- 浏览器只持有独立、受限、HttpOnly 的观察者 cookie；它不是 B 管理员令牌，也没有工具执行权限。
- 不要在浏览器控制台人工拼接管理请求或新增通用代理。
- 使用演示数据库时指定新文件名；不要拿历史业务库做演示或清空历史库。
- 回放文件可能含业务事实。对外发送前按项目交接规则确认范围，并附 SHA-256、session/episode/config、契约版本和非敏感来源说明。

## 11. 建议的首次浏览路线

第一次打开时，可按下面顺序在 5—10 分钟内了解工作台：

1. 第一页开始测试卡：查看 ① 测试方式 / Agent 配置、② 业务案例、③ 连接状态、④ 运行测试四步布局（“启动 Agent”禁用及原因）。
2. 在“运行”选择器选一次本机会话，看结果卡四个数字：已提交退款 / 核验净损失 / 研究赔款 / 运行状态。
3. 展开「详细执行证据」：阅读售后消息与订单商品，展开“业务初态与版本”查看对象映射和哈希免责声明；在事件表筛选 succeeded、rejected、replayed；点击退款事件的“关联交易”，再点“查看关联订单”，体验完整追溯。
4. 点击出口牌“前往下一站 → 风险评估”，看跨运行汇总卡片与每项的 `[范围｜开发｜样本 N]` 标注、“来源运行”折叠。
5. 再点“前往下一站 → 保险方案”，看两套方案卡的“待确定”与工程算例的 illustrative 标记。
6. 点击“走完了 · 回到 Ⅰ Agent 测试”回第一页；用“保存证据回放”下载 JSON，再从运行条导入它，观察页面切换为只读回放并自动展开证据；最后点击“返回本机服务”。
