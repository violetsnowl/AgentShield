# AgentShield 前端工作台操作手册

适用版本：前端 `0.3.0`（演示重构版：极简三页）、B/C `bc-0.3-candidate`、EvidenceBundle schema 3（兼容 schema 1/2）、观察者 `observer-0.1-candidate`、A/C 展示边界 `abcd-results-boundary-0.2-candidate`。

本工作台用于查看企业售后退款沙箱的工程事实、执行证据和已交付的 A/C 候选结果。它不是正式 Agent 控制台；浏览器只显示服务端校验通过的 C `LossResult`、A0 理赔结果和单独标记的工程 Quote 示例，不执行损失判断、保险公式或商业报价。页面中的退款来自开发沙箱的模拟交易，不能直接解释为最终风险、损失或赔款。

> 本轮（2026-10-16）为面向评委的演示重构：删除常驻运行条、出口牌与密集指标卡；每页只回答一个问题。规范豁免与退役清单见 `docs/decisions/UI_DEMO_REDESIGN_2026-10-16.md`。

## 1. 启动工作台

在 PowerShell 中进入项目根目录：

```powershell
cd "C:\path\to\agentshield"
```

首次使用或前端依赖缺失时安装锁定依赖：

```powershell
npm.cmd --prefix frontend ci --ignore-scripts --no-audit --no-fund
```

构建前端：

```powershell
npm.cmd --prefix frontend run build
```

使用独立预览数据库启动：

```powershell
.\.venv\Scripts\python.exe -m scripts.run_workbench `
  --db var/local-preview.sqlite3 `
  --port 8810 `
  --seed-development
```

正常输出类似：

```text
Development sessions seeded: 2; model/payment calls: 0
Workbench: http://127.0.0.1:8810 (...)
```

启动器会自动打开一次带临时本机观察授权的浏览器页面。保持 PowerShell 窗口运行；按 `Ctrl+C` 停止 B 和观察者服务。只关闭网页不会停止服务。

不要只手动输入裸地址 `http://127.0.0.1:8810`。裸地址不含一次性配对授权，可能显示未授权。若自动打开失败，按 `Ctrl+C` 停止后重新运行启动命令。

`--seed-development` 只在当前观察租户没有会话时播种两份开发运行。再次使用同一数据库启动会显示 `seeded: 0`，这是防止重复造数据的正常行为。想查看一套全新示例时，使用另一个尚不存在的数据库文件名，不要删除或覆盖历史数据库：

```powershell
.\.venv\Scripts\python.exe -m scripts.run_workbench `
  --db var/local-preview-02.sqlite3 `
  --port 8810 `
  --seed-development
```

若 8810 端口被占用，将端口改为 8811；浏览器仍由启动器自动打开。

## 2. 先理解页面中的三类身份

页面同时涉及 case、session 和 episode，它们不能混用：

- `case_id`：稳定业务案例，用于关联同一种业务场景。
- `session_id`：一次独立运行。订单、消息、事件、退款和账本都归属于具体 session。
- `episode_id`：本次运行的 episode 标识，用于与 C 的运行记录对接。

相同 case 可以运行多次，但不同 session/episode 的状态和金额必须分开。工作台不会把同 case 的多次运行合并成一次，也不会跨会话汇总退款。

查看完整身份的方式：展开页面下部「查看完整执行记录与核验依据」，在其中的「运行详情（session / episode / 版本 / 来源）」折叠内可看到三项完整 ID 与版本。向队友报告问题或交接证据时，应提供完整运行身份（可手动选取复制），不能只说 case 名称。

## 3. 页面整体结构（演示三页）

顶栏自左至右：品牌标识、三个页面导航（`01 测试案例 / 02 风险结论 / 03 保险方案`，当前页为黄色下划线）、右侧「演示记录」选择器（切换查看的运行）；从交付运行自动跳转后，右上方会出现「← 返回上一位置」。

三页依次是：

1. **01 测试案例**（默认首页）：一笔退款申请，Agent 会怎么处理？——案例摘要、本次执行结果、按需展开的核验与执行记录。
2. **02 风险结论**：目前，我们能证实什么？——动态结论、三个核心事实、三步证据链、审计口径折叠。
3. **03 保险方案**：如何用保险承接这类风险？——Core / Plus 两套研究候选方案卡与测算依据折叠。

每页正文末尾有一行普通的**「← 上一步 / 下一步：… →」文字链接**（第三页为「回到第一步」）用于顺序浏览；只切换页面，不改变当前运行。页脚区有单行免责声明和默认收起的「开发工具」。

第一页自上而下依次是：「**＋新建一次测试**」入口（点击展开 Agent 选择器与「随机抽样并运行」；抽样执行接口未接通前按钮保持禁用并显示准确原因；普通界面不提供事项类别或具体案例的手动选择）、「**测试记录**」列表（两个标签页：**本机测试记录**＝本机 B 创建的会话；**历史测试**＝已交付目录的只读运行。两类记录严格分开、互不混入；点行内「详情」即切换查看该运行）、**案例摘要**（中文案例名、业务请求与订单关键事实）、**本次执行结果**（主事实＝本轮已提交退款；辅助＝运行状态、独立核验、研究赔款三项状态）、可选的**「查看核验与理算详情」折叠**（仅当所选运行在交付目录中有对应条目）和默认收起的**「查看完整执行记录与核验依据」**（运行详情、订单与商品、售后消息、业务初态、事件、退款、账本、追溯与工单都在这里面）。

顶部提示条含义：

- 黄色提示条 `A/C 交付证据只读视图`：正在查看本地交付目录中校验通过的运行；属于开发运行，不连接外部服务。点「返回本机服务」回到本机 B。
- 黄色提示条 `离线只读回放`：正在浏览导入的 JSON 文件，不读取 B；内容未经签名认证。
- 「重新理算」仍有意禁用（前端不执行 A 的保险公式）；真实 Agent 运行器未接通，开发工具中对此有注记。

## 4. 选择、创建运行

### 4.1 选择已有运行

顶栏「演示记录」与第一页「测试记录」列表是同一选择状态的两个入口，都可切换运行。顶栏下拉内部分为两组：

- **本机会话**：格式 `case_id ｜ session_id`，来自本机 B 的会话目录。
- **已交付历史运行**：格式 `真实模型 / Mock · 标签 ｜ …<session 后 8 位>`，来自 A/C 交付目录中已校验的运行。

首次打开时，页面会自动选中交付目录中证据链最完整的真实模型运行（只读交付视图）；也可以随时在下拉中切换。切换运行后，页面停留在当前页并重新读取该 session 的证据、事件和账本；旧运行的迟到响应不会覆盖新选择。如果选中的是**只存在于交付目录**的运行（本机会话中没有对应条目），页面会自动跳到「01 测试案例」并展开「查看完整执行记录与核验依据」，可用「← 返回上一位置」回到刚才的页面。

第一页「测试记录」的标签页跟随当前所选运行的归属自动切换，也可以手动切换浏览：**本机测试记录**列出本机 B 创建的会话（运行状态、已提交退款；C 核验 / A 理算尚未接入本机链路，对应列显示「未接入」，未接入 ≠ 零损失）；**历史测试**列出已交付目录的只读运行（来源、运行状态、已提交退款、候选应退、核验净损失与研究赔款；未核验处显示「待核验 / null」，未知不记零）。点某行的「详情」选择该运行，与顶栏选择器等效。

来源标签只说明管理方记录的执行来源；`observed_agent_execution`（真实模型）标签本身不能证明真实模型运行，仍需 C 提供完整记录。真实模型、Mock 与规则基线分组分开标注，不作性能比较。

### 4.2 创建业务会话（开发工具）

创建新会话在页脚「开发工具」中：先选择业务案例（受控开发模板 `dev-refund-v1`、`dev-refund-v2`、公开/压力案例分组，A 公开固定案例归入「其它案例」组；名称只描述公开业务事实，不暗示正确答案），再点击「创建业务会话」。该操作只创建一份新的业务初态，生成新的 session/episode 和运行对象；**不会启动 Agent、调用模型、提交退款或产生账本金额**。新会话显示「尚无执行事件」和「没有资金变动」是正常现象。

如果创建时出现超时或「响应可能丢失」，不要立即重复点击。会话可能已经在服务端创建成功，应刷新页面或重新查看运行目录，先按 session 核对，再决定是否重试。

启动参数 `--seed-development` 产生的两份样例与页面「创建业务会话」不同：播种脚本会经真实 B HTTP 写入明确标记的开发退款、拒绝、重放和工单事实，用于展示完整链路。

第一页的「＋新建一次测试」是面向普通流程的入口：Agent 选择器仅列出 `configs/runner` 中已注册的运行配置（真实模型配置标注「需付费授权」，规则基线为确定性免费，接口模拟仅用于记录）。**抽样执行接口尚未接入**（后端任务抽样与受控执行链路未接通），因此「随机抽样并运行」保持禁用并注明原因，不会产生任何记录；接通后每次运行将独立建会话、不重复提交资金。页脚「开发工具」中的「创建业务会话」是保留的独立调试入口（用于固定案例回归），不属于普通测试流程。

## 5. 业务事实与初态（第一页 · 完整执行记录折叠内）

本节内容位于第一页「查看完整执行记录与核验依据」展开后的**业务事实区**，回答“这个运行面对什么业务事实”。

### 5.1 案例摘要（默认可见）

页面默认显示中文案例名和业务请求；`开发数据 · 待审` 表示该场景尚未由 A/C/D 冻结为正式任务。订单一行显示实付 / 已退 / 剩余与状态；资格未满足会如实标注。

### 5.2 售后消息

每条消息显示：客户自然语言内容、`message_id`、是否附带结构化确认、展开后的确认订单、商品和数量范围。自然语言消息本身不一定构成退款授权；后端退款提交依赖结构化确认、订单版本、商品数量及资格等事实。

### 5.3 订单与商品

每个订单分别显示订单 ID 和状态（已支付 / 部分退款 / 已退款）、实付 / 已退 / 剩余金额、每件商品的购买/已退/可退数量、分摊实付与已退金额、模板资格及运行内商品 ID、订单版本和模拟原渠道。

金额以整数分保存，界面转换为人民币显示。商品「符合模板资格」只是当前开发模板的冻结事实，不代表 A 已完成正式业务审核。fixture v2 的期初历史退款单独标注（session 开始前，不计入本轮）。

### 5.4 业务初态与版本

此区域显示模板版本、政策版本、执行环境版本、稳定 case 和规范初态哈希。可展开「模板 → 本次运行对象映射」与「冻结的规范业务初态」、「原始政策文案」。

页面显示的 SHA-256 是文件声明值，浏览器没有重新计算，也不是签名、来源认证或风险成绩。schema 1/2 的旧证据可能没有上下文、映射和哈希；页面会显示 `legacy_unavailable/null`，不会补造。v1 历史政策原文中的「工单尚未接入」会原样保留并提示历史差异。

## 6. 执行证据与资金账本（第一页 · 完整执行记录折叠内）

此部分回答“服务端实际记录了什么，以及资金事实能否追溯”。

### 6.1 顶部汇总

三条汇总显示：已提交退款总额（只对唯一、已提交的交易求和）、商户余额、客户余额（本次运行最终快照）。这些金额是模拟交易事实，不是保险赔款、损失或商业报价。

### 6.2 执行事件

事件按 session 内 `seq` 排序，**一次性加载**（不再分页）。状态只有四种：

- `succeeded`：本次请求成功处理。读取工具成功不等于发生付款。
- `rejected`：请求被参数、权限、版本或协议规则拒绝，没有新增提交资金。
- `replayed`：命中已成功提交的原幂等键，返回原结果，本次新增资金为 0。
- `error`：服务端处理发生错误；不能据此假定业务一定未提交，需结合退款历史和账本恢复判断。

「本次提交」列显示该事件新增的 committed amount。退款首次成功可能非零；查询、工单、结束声明、拒绝、错误和原键重放通常为零。点击「事件详情 N」可查看 `event_id`、`request_id`、`call_id`、幂等键和原始事件 JSON。

### 6.3 交易追溯

退款事件旁的「关联交易」或账本中的交易 ID 会打开「交易追溯」：提交事实 → 双边守恒账本 → 同交易事件 → 关联订单。点击「查看关联订单」会回到业务事实区并滚动、高亮精确订单。若证据缺少退款或账本一侧，页面会明确显示追溯不完整，不推测缺失事实。

### 6.4 人工审核工单

工单显示 category、status、ticket ID、缺失事实和关联记录。`open` 不等于已经裁决；工单本身不产生资金；schema 1 的旧证据可能没有工单集合，「未记录」不等于「确认没有」。

## 7. 风险结论（第二页）与保险方案（第三页）

### 7.1 风险结论（第二页）

第二页不重复单次结果，汇总**本机交付目录中已校验运行**范围的统计：

- **结论区**（页首）：由当前数据实时生成。样本不足时显示「整体风险：证据不足」并给出覆盖数字（如「当前只有 1 / 15 次运行具有已核验损失结果，暂不足以估计整体风险」）；数据充分时按真实结果更新表达。
- **三个核心事实**：①运行数量（全部为开发运行，不计入正式 56 次）；②独立核验覆盖（已核验 / 全部，待核验保持 `null`、未记零；「待核验 ≠ 任务升级」）；③已核验样本净损失（先给覆盖限定，零损失不等于整体风险为零；无样本时显示「证据不足」）。
- **三步证据链**：Agent 执行记录 → 独立损失核验 → 研究保险理算，每步显示当前真实状态。
- **「查看完整统计与数据口径」折叠**（审计用）：开发运行来源构成（真实模型 / Mock / 规则基线分开计数，不作性能比较）、任务升级（`task_outcome=escalated`）与人工工单（B 证据 `human_reviews`，独立维度）、按业务类别统计表、B-SCALE 未接入说明、以及完整口径说明。各来源运行名单在该折叠内的「来源运行 / 待核验运行 / 升级运行」小折叠中。

### 7.2 保险方案（第三页）

第三页展示 A 交付的 A4 两套研究候选产品（来源：`configs/insurance/research_products_A4_candidate.json`，schema `AgentShield.two_research_products.v0.1`，状态 `product_design_candidate_not_bound`）：

- **AgentShield 操作差错基础保障（Core）** 与 **AgentShield 操作差错增强保障（Plus）** 两张卡：被保险人、保障责任（Plus 增强表述引用 A4 源数据）、**「参考保费」行**（数据未到位时显示「待定」，行内注「参数审定与核验样本齐备后测算；研究用途 · 非商业报价」）、免赔额 / 赔付比例 / 单次赔付限额 / 年度累计赔付限额的真实状态，以及「方案参数待审」「研究候选 · 非商业报价」标签。
- A4 中为 `null` 的参数一律显示 **「待定」**，绝不用旧 A0 研究合同的数值替代；商业保费状态为 `insufficient_evidence`（证据不足，不出具数字）。
- Plus 的处置费用附加责任标记 **「可选 · 待实现」**；年度累计限额理算尚未实现。
- 「查看保障条款与测算依据（A4 候选）」折叠列出 premium_method 口径与 data_requirements；「单事件理算工程示例（不代表 Core / Plus 保险报价）」折叠保留旧 A0 单事件工程理算与 QuoteResult 工程样例（`illustrative`），其中明确标注：**A0 工程理算示例，不代表 Core / Plus 产品报价**。

正式保额与商业保费由 A 后续审定；B/A 提供只读产品接口后，前端只需替换数据加载层（`frontend/src/data/a4Products.ts`），页面无需重新设计。

## 8. 保存和导入证据回放（开发工具）

### 8.1 保存当前回放

选择一次本机运行后，在页脚「开发工具」中点击「保存证据回放」。浏览器会下载 `evidence-<session_id>.json`（当前 EvidenceBundle 的无凭据快照）。保存操作不执行工具、不提交退款，也不停止本机服务。

### 8.2 导入回放

在「开发工具」中点击「导入回放」，选择不超过 5 MiB 的 JSON 文件。工作台会在浏览器本地读取，不上传文件，并进行：

- schema 1/2/3 校验。
- session/episode 和运行归属校验。
- 事件 seq、交易 ID 和重复记录校验。
- 整数金额及安全范围校验。
- 退款行小计、账本守恒、期初/期末余额、订单商品增量和交易关联校验。
- 凭据字段检查。

合法文件载入后，顶部显示「离线只读回放」提示条，页面自动切到第一页并展开「查看完整执行记录与核验依据」。此时不调用 B、不能创建会话或执行工具、切换三个页面只读取本地内容，也可以再次保存该快照。点击「返回本机服务」重新读取本机运行目录。

如果导入文件自相矛盾或格式不合法，页面拒绝新文件，并尽量保留此前合法显示。文件内部一致不证明来源真实、业务合法或模型真实执行；回放文件没有签名，不能当作本机最新状态。页面已经加载后，schema 1/2/3 文件的断网回放已验证；断网冷启动或刷新网页尚未实现。

## 9. 刷新、错误和空状态

### 刷新本次运行

本机服务模式下，在「开发工具」中点击「刷新本次运行」，重新获取当前 session 的证据、事件和账本。适合在服务端刚发生新事件后使用。如果读取期间运行发生变化，导致证据、事件页或账本不能组成一致快照，页面会要求刷新，而不会混合新旧事实。

### 读取失败

出现「当前数据未能加载」时：①确认启动工作台的 PowerShell 仍在运行；②点击「重试读取」；③若观察授权已过期或服务已重启，按 `Ctrl+C` 停止旧进程并重新运行启动命令，让浏览器重新完成一次性配对；④仍失败时保留页面错误和终端输出，不要通过关闭鉴权或修改 CORS 规避。

### 空运行

新创建会话只有业务初态，没有事件、退款和账本。这不是加载失败。当前没有真实 Agent 运行器自动执行它。

### 创建结果未知

若创建请求超时或响应丢失，页面会提示先核对运行清单。不要盲目重复提交；服务端可能已经创建成功。

## 10. 安全使用要求

- 工作台仅用于本机 `127.0.0.1` 开发环境，不要改为局域网或公网部署。
- 不要把管理员令牌、session_token、模型 API Key 写入前端源码、浏览器存储、URL、截图或日志。
- 浏览器只持有独立、受限、HttpOnly 的观察者 cookie；它不是 B 管理员令牌，也没有工具执行权限。
- 不要在浏览器控制台人工拼接管理请求或新增通用代理。
- 使用演示数据库时指定新文件名；不要拿历史业务库做演示或清空历史库。
- 回放文件可能含业务事实。对外发送前按项目交接规则确认范围，并附 SHA-256、session/episode/config、契约版本和非敏感来源说明。

## 11. 建议的首次浏览路线

第一次打开时，可按下面顺序在 5–10 分钟内看懂整条链路：

1. 打开即落在「01 测试案例」：看案例摘要（这是什么业务）与本次执行结果（这轮实际提交了多少退款、有没有对应的核验与理算结果）。
2. 点开「查看核验与理算详情」（如所选运行有对应条目），看独立核验与赔款状态；点「加载关联业务证据」会切到该运行的只读交付视图。
3. 展开「查看完整执行记录与核验依据」：阅读售后消息与订单商品；点退款事件的「关联交易」，再点「查看关联订单」，体验完整追溯；需要时查看「运行详情」中的完整身份。
4. 点页面末尾「下一步：02 风险结论 →」：看页首结论、三个核心事实与三步证据链；想核对口径时展开「查看完整统计与数据口径」。
5. 再点「下一步：03 保险方案 →」：看两张候选方案卡的「待定」与工程算例的 illustrative 标记。
6. 点「回到第一步：01 测试案例 ↺」回第一页；需要时在「开发工具」中用「保存证据回放」下载 JSON、用「导入回放」观察只读回放模式，最后点「返回本机服务」。
