# AgentShield V1.1｜D 独立任务卡

这是主文档的对应角色节选，不替代共同接口、红线和验收要求。先读主文档第 2、3、5、17—21 节。

**统一级别：**L0 连通验证（不可单独算最终交付）；L1 最低完整交付；L2 标准参赛版；L3 可选增强。

**统一规模：**L1：24 常规＋4 压力、1 套真实配置各 2 次＝56 次，规则基线另 28 次。L2：48＋12、2 套各 2 次＝240 次，规则基线另 60 次。任务数量不是统计可靠性认证。

**交接证据：**产物路径、版本、执行命令、输入输出、实际测试结果、已知缺口及接收人确认。共同链路未通过，不因个人空闲自行扩到 L3。

**日程：**北京时间；10/12 工程闭环，10/13 中午真实闭环，10/15 中午 L1 发布候选，10/17 发布检查与提交缓冲。L1 最终完成还须通过 J4，不能将发布候选当已交付。

## D 任务卡：前端、任务复核与交付协调

**最终责任：系统能让第三人看懂、操作、查证并复现；团队产物真正拼成一条链。**主目录 frontend、tests/e2e、release；与 A 共管任务复核。

### L0｜尽早做出可联调工作台

D0-1 用共同 fixture 和接口样例建单页四区骨架，先显示真实数据结构，不等待后端全部完成。

D0-2 与 A 分担 12 个工程任务的独立核对，检查公开证据能否推得合法结果，反馈缺字段；不得将正式留出 Gold 放进前端构建或提示词调优上下文。

D0-3 建立验收清单、阻塞板和论文骨架；组织一次从操作到金额的联合走查，记录责任人而非自己代修全部问题。

**交付/验收：**前端能显示统一样例；至少一个数据字段可从界面追溯到事件；有可复现的接口缺陷清单。

### L1｜交付可操作的四区界面与完整材料

D1-1 接通企业实验场、执行证据/账本、配置比较、合同/情景成本四区。至少能发起获授权的轻任务、回放真实轨迹、查询损失依据、修改合同并重算。

D1-2 显示正常/压力、真实执行/回放/工程样例、样本量、失败和未知状态；待评测不填随机数字，零观测和证据不足有明确空状态。

D1-3 与 A 完成 28 个正式任务双人复核和 manifest 检查；按验收表逐项收证据，组织第二台环境或干净目录的独立启动与断网回放。

D1-4 写界面、演示与复现章节约 1500 字；收齐其他三人原稿，只做结构与格式整合；完成匿名 Word/PDF、60—90 秒实际软件演示视频及发布备份。

**验收：**任意展示赔款可点到任务、账本、Gold 依据与公式；关闭网络不影响已有轨迹回放和离线理算；完整软件与文件交给另一队员仍可使用。对应 R07/R08/R09/R10。

### L2｜改善表现力和证据阅读

完善两配置并排比较、任务类别筛选、自然/压力标签页、真实时间线、可解释费用分解；整理关键结果图和演示节奏。所有视觉强调由实际数据驱动，不预编“必然翻车/必然反转”的剧情。

### L3｜增益必须服务理解

可改善报告导出、审计导航、演示交互和可访问性，不做 3D 炫技、虚假实时大屏或替代实际结果的动画。先验证所有 L1 数据绑定，再做视觉优化。

**依赖与补位：**等待 B 时用契约 Mock；等待 C 时只标开发样例。A 负责论证终审，各模块作者修自己的内容与数值；D 不是最终材料的唯一作者。
