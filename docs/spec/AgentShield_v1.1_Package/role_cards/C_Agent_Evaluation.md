# AgentShield V1.1｜C 独立任务卡

这是主文档的对应角色节选，不替代共同接口、红线和验收要求。先读主文档第 2、3、5、17—21 节。

**统一级别：**L0 连通验证（不可单独算最终交付）；L1 最低完整交付；L2 标准参赛版；L3 可选增强。

**统一规模：**L1：24 常规＋4 压力、1 套真实配置各 2 次＝56 次，规则基线另 28 次。L2：48＋12、2 套各 2 次＝240 次，规则基线另 60 次。任务数量不是统计可靠性认证。

**交接证据：**产物路径、版本、执行命令、输入输出、实际测试结果、已知缺口及接收人确认。共同链路未通过，不因个人空闲自行扩到 L3。

**日程：**北京时间；10/12 工程闭环，10/13 中午真实闭环，10/15 中午 L1 发布候选，10/17 发布检查与提交缓冲。L1 最终完成还须通过 J4，不能将发布候选当已交付。

## C 任务卡：Agent、独立核验与执行实验

**最终责任：确实测试了什么 Agent、它做了什么、产生的资金后果能否由独立代码复算。**主目录 runners、evaluator、experiments。

### L0｜交付真实执行证据

C0-1 做 MockAdapter、统一循环和 HTTP 客户端，先用 B 的固定样例跑通；模型输出只能走白名单工具，不直连数据库。

C0-2 实现一套真实适配器与预算控制，获授权后完成至少 3 次开发运行，覆盖普通退款、部分退款和需人工场景；记录实际成功或失败，不保证模型全部做对。

C0-3 用 A 的工程 Gold 独立实现损失核验器；与 B 的事实记录对齐，不调用 B 的“正确金额/正确动作”判题函数。

**交付/验收：**Mock 与真实运行标签不同；保存可追溯轨迹；核验手算例一致；一个真实任务的行为能进入前端和保险计算。

### L1｜交付可比较、可追溯的全量结果

C1-1 实现确定性规则基线，依据 A 的公开决策表，经相同工具接口执行；不读取 Gold，不引入第二个 LLM。

C1-2 完成至少 10 次开发成本预试，冻结提示词、配置、运行预算和失败补跑规则；正式完成 56 次真实运行＋28 次规则基线执行。

C1-3 输出逐 episode 清单、逐 case 聚合前记录、LossResult、失败/缺配对表和成本记录；把精确保险理算与 B0/B1 交给 A，而非继续包办。

C1-4 写方法/执行实验初稿约 2600 字，说明适配、独立性、预算、失效类型与可复现边界；不把 seed 宣称为模型逐字复现保证。

**验收：**正式结果有冻结 manifest；无 Gold 泄漏；所有已提交资金后果均入账；同任务重复未当作独立业务样本。对应 R01/R03/R05/R06/R08/R09。

### L2｜增加第二配置及稳定性比较

在预登记和预算允许下接第二真实配置，补足 240 次总运行；优先共享同一运行框架与环境。核对两配置配对、重复内波动、运行失败和模型专有参数；没有跨模型就不写跨模型。

### L3｜只做有证据价值的扩展

补足最多 720 次总运行，或提供按任务家族的稳定性数据；新增运行只在冻结清单及费用上限内。不要同时接五个提供商，不开发无限自动补测或任意外部 Agent 平台。

**依赖与补位：**B 的沙箱未好先做 HTTP Mock；A 的正式 Gold 未冻结只用工程样例；D 协助批次清单与失败归档。C 不再负责论文统稿、视频和权威保险模块。
