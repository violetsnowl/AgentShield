# AgentShield V1.1｜A 独立任务卡

这是主文档的对应角色节选，不替代共同接口、红线和验收要求。先读主文档第 2、3、5、17—21 节。

**统一级别：**L0 连通验证（不可单独算最终交付）；L1 最低完整交付；L2 标准参赛版；L3 可选增强。

**统一规模：**L1：24 常规＋4 压力、1 套真实配置各 2 次＝56 次，规则基线另 28 次。L2：48＋12、2 套各 2 次＝240 次，规则基线另 60 次。任务数量不是统计可靠性认证。

**交接证据：**产物路径、版本、执行命令、输入输出、实际测试结果、已知缺口及接收人确认。共同链路未通过，不因个人空闲自行扩到 L3。

**日程：**北京时间；10/12 工程闭环，10/13 中午真实闭环，10/15 中午 L1 发布候选，10/17 发布检查与提交缓冲。L1 最终完成还须通过 J4，不能将发布候选当已交付。

## A 任务卡：业务、保险计算与研究结论

**最终责任：说清业务允许做什么、怎样算损失与赔款，以及数据实际支持什么结论。**主目录 docs/business、configs/insurance、actuarial；与 D 共管任务和 Gold。

### L0｜先把标准算清

A0-1 写最小业务规则、四类定义和基线决策表；与 D 审定 12 个工程任务，保证关键信息可查询。

A0-2 提供第 9 节金额测试及 expected 结果，明确正常支出、少退、多退、追回和人工审查的差别。

A0-3 编写最小保险理算纯函数与手算测试，提供固定合同和一份 QuoteResult 样例，不等待 C 的真实数据。

**交付/验收：**business_policy.md、分类与合同配置、工程 Gold、test_claims；D 可按证据复算，C 可用算例独立开发。未通过不扩任务量。

### L1｜交付可计算的保险闭环

A1-1 与 D 完成 24 常规＋4 压力任务的双人审定和冻结清单；四类各 3 开发/估计＋3 留出，登记 family/parent 和复核记录。

A1-2 完成 actuarial 的责任判定入口、事件赔款、B0/B1、权重校验和证据状态；预登记至少两个目标业务组合。责任不清可待审，不能伪造自动判断。

A1-3 用 C 的全量损失表运行统计与留出误差，核对零损失、缺类别、未知金额及越界输入；改合同不重跑 Agent。

A1-4 写本模块正式报告初稿，目标约 2700 字，含问题、业务、保险方法、发现和限制；对总论证负责，但不代写 B/C/D 章节。

**验收：**同一已冻结账本可以重算；至少两组手工输入与程序一致；每个报价都能追到合同、类别样本和原始损失。对应 R03/R04/R06/R08/R10。

### L2｜增加证据，不堆新概念

与 D 扩到 48＋12 并保持留出纪律；对两套真实配置输出相同口径图表、多个预登记业务组合及误差说明；审核业务成功与赔款差异是否真的存在。可增加探索性簇自助范围，明确其样本条件。

### L3｜条件启用

仅在参考经验可比且参数可验证时做 B2；或做按序累计限额/共同故障情景。二者均可不启用，不能为填满页面随意设参数。不得牺牲 Gold 复核、B0/B1 或论文真实性。

**依赖与补位：**等待 C 数据时先用固定工程台账；Gold 由 D 分担；B/C 只帮助接口与测试，不把全部精算模块退回 C。
