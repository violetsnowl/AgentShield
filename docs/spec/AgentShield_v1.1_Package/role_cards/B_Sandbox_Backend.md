# AgentShield V1.1｜B 独立任务卡

这是主文档的对应角色节选，不替代共同接口、红线和验收要求。先读主文档第 2、3、5、17—21 节。

**统一级别：**L0 连通验证（不可单独算最终交付）；L1 最低完整交付；L2 标准参赛版；L3 可选增强。

**统一规模：**L1：24 常规＋4 压力、1 套真实配置各 2 次＝56 次，规则基线另 28 次。L2：48＋12、2 套各 2 次＝240 次，规则基线另 60 次。任务数量不是统计可靠性认证。

**交接证据：**产物路径、版本、执行命令、输入输出、实际测试结果、已知缺口及接收人确认。共同链路未通过，不因个人空闲自行扩到 L3。

**日程：**北京时间；10/12 工程闭环，10/13 中午真实闭环，10/15 中午 L1 发布候选，10/17 发布检查与提交缓冲。L1 最终完成还须通过 J4，不能将发布候选当已交付。

## B 任务卡：企业沙箱、交易与接口

**最终责任：Agent 的每一步操作都有确定、受约束、可追溯的业务后果。**主目录 sandbox、api、数据库迁移与 contracts 主文件。

### L0｜交付可独立测试的交易底座

B0-1 建立最小订单/商品/售后/退款/账本结构，从固定 fixture 创建新会话；先实现查询与退款主链路。

B0-2 实现权限、数量、累计上限、原路退款、幂等及版本检查；每笔交易与请求状态原子提交。

B0-3 给 C/D 提供可直接调用的示例请求和响应，完成核心控制测试；与 C 合审 ToolEvent，不等待模型适配完成。

**交付/验收：**可启动后端、数据库初始化、开发 fixture、控制测试及 HTTP 示例。重复请求只入账一次，跨会话读取/写入被拒绝，金额守恒。

### L1｜交付完整沙箱与前后端接口

B1-1 七个公开工具全部工作；submit_human_review 真实生成待办，finish_case 不篡改交易；运行期间只允许授权对象。

B1-2 提供会话/实验状态、事件查询、只读账本、独立核验与报价的管理路由；仅调用 C/A 模块，不复制公式。后端启动任务交给 C 的队列入口。

B1-3 处理响应丢失、未知提交状态及新键重复操作；保留中断前资金后果。为 D 提供完整正常、拒绝、待审与出错接口样例。

B1-4 写技术章节约 2200 字：业务模型、权限、幂等、事务、接口与复现；随代码交付迁移和初始化命令。

**验收：**C 的真实运行器不直接访问数据库即可完成任务；D 不靠手改 JSON 就能查真实事件；关键失败算例全部通过。对应 R01/R02/R03/R07/R09。

### L2｜改善稳定性与拟真细节

支持 60 个任务快照及两个配置批次的可靠隔离；完善订单历史、客户更正和状态变化；实测队列/数据库锁冲突与恢复。增加背景订单只服务查询演示，不增加样本宣称。以实际测试记录报告吞吐，不凭估算写性能成果。

### L3｜有必要才扩容量

在不改变业务语义前提下完善任务生成、压力状态和可重放快照；可做单机容量测试。禁止顺手重构微服务、接真实支付或引入全新业务线。

**依赖与补位：**A 给业务语义；C/D 给消费者字段需求。技术阻塞由 B 定位，C 查协议、D 提供可复现请求；任何人改接口先更新版本和示例。
