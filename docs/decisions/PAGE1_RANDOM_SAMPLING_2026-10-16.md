## 1. 需求要点（照录并转为行为约束）

- 删除普通用户界面中的事项类型选择器、具体测试案例选择器与固定案例手动挑选入口；保留「＋新建一次测试」、Agent 选择器（仅真实已注册配置）、一个主要按钮「随机抽样并运行」、下方测试结果列表、「下一步：风险结论」导航。
- 测试记录默认不混入历史数据；历史已完成运行经「历史测试」查看，不得冒充本次新建运行。

- 严禁：用四固定案例冒充十万抽样；前端 `Math.random()` 造假任务；编造应退金额或 Gold；把请求金额当作真实损失。
- 抽样执行接口未完成时：按钮不得伪装成功；应显示准确不可用状态；历史真实运行仍可查看。
- 可保留独立开发调试入口（历史固定案例回归），但不得占据普通用户首页。

## 3. 数据与安全接口设计（草案；尚未实现——本轮不建假接口）

未来接口（由后端实现，前端只消费）：

```text
POST /observer/api/sampling-runs        （或未来 B/C 受控执行入口；路径以实现方为准）
  request: { config_id }                ← 无类别、无案例、无金额参数（禁止前端挑题）
  backend:
    1) 以服务端种子从 B-SCALE 任务池（6,105 项）按总体构成比例抽取一条未用任务；
       记录 { pool_version, seed, batch_id, task_id, class } 供复现与审计
    2) 校验可执行条件（fixture 可物化 + 义务定义可用 + 未执行过）
    3) 生成受控案例（B 注册流程）→ 建立隔离 session + episode（幂等，防重复资金提交）
    4) 经 C 受控运行器执行所选 config（付费模型需已授权 + 预算上限）
    5) 保存 B 证据 / C LossResult / A 理算（或待审）→ 交付目录条目
    6) 返回 { run_id } → 前端把该记录加入「本机测试记录」
  失败：不产生假记录；返回明确错误；前端显示失败原因。
```

## 4. B-SCALE → 可执行 B 受控案例：缺口清单（2026-10-16 深夜核实）

已核实事实：B-SCALE 数据集本体与审计材料**不在本工作副本、不在本机 E/D/F 盘、不在本仓库任何分支**（仓库内仅文档引用其规模口径：10 万模拟订单 / 10,145 退款请求 / 6,105 潜在任务 / 四类 `whole-*`、`partial-*`；`VERSION_AND_DIFF.md` 亦记「未假设 B-SCALE 本地十万订单分支已经进入 main」）。

缺口（把抽样任务变成 B 受控案例还缺什么）：

1. **任务池数据本体**（任务 ID / 批次 / 类别 / 订单与商品 / 请求与确认结构）——待 B 提供或指明位置。
2. **后端抽样器**（总体版本、种子、四类构成一致、批次与任务记录）——未实现。
3. **任务 → fixture 映射**：逐字段映射到 `sandbox/fixture_models.py` 的开发模板结构，并通过 `sandbox/fixture.py::validate_fixture` 全量守恒校验（分摊、期初历史、候选范围、消息/确认额度、余额守恒、ID 唯一）。
4. **注册机制**：fixture 只能由源码 allowlist（`contracts/fixture_ids.py`）+ `sandbox/fixtures/generated/registry.json`（含 SHA-256 钉扎）注册，HTTP 无注册接口（有意设计）。抽样执行需要 B 提供受控注册流程（确定性物化 + 哈希登记 + allowlist 扩展），不得绕过。
5. **义务定义**：C 核验需要 obligation_spec 才能给出 `verified` / `legally_due`；抽样任务无义务定义 → 只能 `needs_review`（净损失 null）。需要 A/C 提供可审定义务生成流程（或明确接受 needs_review 输出）。
6. **C 运行器接入**：`experiments/run_dev.py` 目前按计划文件（`experiments/plans/*.json`）运行固定案例；需 C 增加「按任务配置运行」的入口或计划生成器。付费门（`runners/config.py: paid_authorization`，默认关）与预算上限（`max_run_cost_cny`）已就位。
7. **交付目录**：运行产物落 `artifacts/c_l0/runs/<batch>/<run>/`（当前被 `.gitignore` 保护，跨机器需人工传递）；新记录被工作台自动读取（`workbench/integration_results.py` 校验完整交付条目）。
