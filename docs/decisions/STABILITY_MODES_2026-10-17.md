# 稳定批次与双模式（2026-10-17）

- 范围：`feature/research-risk-contracts` 上的 D 线稳定性修复 + 第一页双模式 + 第二、三页联动（用户四优先级）。
- 结论摘要：HANDOFF「批次完成后第二、三页偶发卡住」的机制已定位（三个独立根因，均有取证），已修复并经端到端验证；双模式 UI 与诚实不可用态已落地；真实 Agent 实测保持不可运行（接口草案待与 C/A 对齐）。

## 1. 根因与修复（第一优先级：稳定现有系统）

### 1.1 「批次完成后界面不刷新、看似卡住」——轮询回填自我取消（真实根因）

批次完成轮询处理里，`setBatchStatus(next)` 先于 `await api('api/integration-runs')` 执行；该 setState 触发轮询 effect 的依赖（`batchStatus.status`）变化 → React 立即清理旧 effect（`active=false`）→ 目录回填在随后的 `if (!active) return;` 处**自我取消**。客户端此后停留在批次完成前的旧目录快照。

- 取证（探查 4，网络级）：完成瞬间客户端已成功收到含新批次的新目录（runs 34→40），但界面标签停在「当前批次（0）/ 历史（34）」（34 ≠ 40，差 6 恰为新批次行）；刷新页面（重挂载路径）后立即正常（当前批次（6）/ 历史（34））。
- 修复：完成分支改为**先取权威目录、再更新批次状态**（两次 await 之间依赖不再变化，回填不会被清理），并在代码内注明原因；`else` 分支保持逐 tick 推进。
- 说明：HANDOFF 提到的 `4a98607` 在本仓库历史中不存在（其远程对应为 `9b0992e`，仅处理了「研究情景在观察者配对前发起」的门控，未覆盖完成回填路径）。

### 1.2 研究情景一次性加载：无重试、无错误态 → 永久「正在汇总」

旧实现只在 `catalogReady` 后单发一次 `api/research-scenario`，失败仅写一条临时 actionError，`scenario` 永久为 null，第二、三页永远停在「正在汇总测试与研究情景」直到刷新。

- 修复：加载改为显式状态机（`loading / ready / error`）+ 自动重试（0.6s、1.2s 退避，最多 3 次）+ 显式错误区块与「重试读取研究情景」按钮；成功路径不变。
- 浏览器验证：故意令前 3 次响应 502 → 页面出现显式错误态；解除故障点击重试 → 页面恢复（检查项固化在 `frontend/tests/browser.mjs`）。

### 1.3 运行明细拉取风暴：三处 `Promise.all` 全量并发

第二页、第三页各自 `Promise.all(runs.map(detail))`，第一页列表另有独立一套；100 条批次 ≈ 100 并发请求轰击本机单进程服务，叠加 8 秒超时容易整页失败。

- 修复：收敛为 App 级**共享明细缓存**（`runDetails`）：6 路有界并发、单条失败重试一次、错误槽位保留、列表/第二页/第三页消费同一缓存且失败可一键重试；统计 fail-closed（有明细读取失败或未就绪时不生成不完整口径的统计）。
- 附：第三页「当前批次单条理赔状态」折叠网格类名由 `.plan-grid` 改为 `.engineering-grid`（消除与主体网格的选择器二义，样式不变）。

### 1.4 批次身份重启即失：内存态丢失 → 历史被当「当前批次」混算

`BScaleBatchManager` 状态原为纯内存；服务重启后 `batch_id` 丢失，前端会把全部历史运行均匀当作「当前批次」统计。

- 修复（服务端）：批次状态原子持久化到 `var/bscale_authorization/current_batch.json`（start/complete/fail 三处落盘）；启动时恢复——仅当该批次证据目录确有运行时恢复，被中断的 `running/queued` 明确标为 `failed（BATCH_INTERRUPTED）`，幽灵状态忽略为空闲。
- 修复（前端）：没有批次时不再冒充「当前批次」，页首如实显示「尚未运行本机批次；以下合计覆盖全部已交付开发运行（历史）」；有批次时标识批次 ID，与历史严格分开。
- 单元测试 6 例（`tests/test_bscale_batches.py`）：恢复完成批、幽灵批忽略、中断转失败、外来/非法状态拒绝、start 先落盘后完成、单飞约束保持。

### 1.5 null ≠ 0 加固

- 「已核验但缺金额」由合计中单列：按业务类别表显示「证据不足」（不再可能以 0 参与展示）、审计口径新增一条「核验缺口」说明；`riskMetrics` 单测固化（测试 4）。
- 第二页核心事实维持「待审 N 条；null 未记为零」；批次明细失败重试按钮就位。

## 2. 双模式（第二优先级）与三页联动（第三优先级）

- **模式选择器**（第一页「＋新建一次测试」内）：`研究情景演示`（默认）/ `真实 Agent 实测`；模式写入 URL（`mode=real` 显式，demo 为默认不入 URL），第二、三页均显示「模式 + 当前批次 ID」横幅。
- **研究情景演示**：即现有免费规则基线批次（操作者可用 `--batch-size` 调 1–100，浏览器不可选），保留 1% 预设事故率与 ¥31,746 / ¥25,641 / ¥35,866.88 情景数值；批次 ID 贯穿三页。
- **真实 Agent 实测（未接通）** ：两个按钮（运行 1 条 / 运行小批量 ≤10 条）保持禁用，逐条列明原因（C 后端 Runner 未接通 / 未授权付费 / B-SCALE 源未配置）；前端绝不直连模型或持有 API Key。
- **第二页真实区块**「本批次执行结果」：运行/已核验、操作错误（未正常完成/转人工）、损失发生率、经济损失；核验不完整时显示「数据不足」，并明示「真实模式不采用 1% 情景假设」；研究情景块在真实模式下加「演示用假设 · 非本批次实测」标注。
- **第三页真实区块**「样本外推参考保费」：`P =（1+附加比例）× 年度任务量 ×（已核定正赔款事件数 ÷ 样本量）× 平均单次赔款`；三态——全部有效核验且赔款均为 0 → ¥0；核验不完整或保险责任未确定 → 「数据不足」不出数字不能生成合同；其余出参考值。合同为「样本外推参考合同」（编号前缀 `SIM-sample-extrapolation-`），与演示合同的文字与编号体系明确区分；两者均为小样本研究口径，非商业报价。
- **与 C/A 的接口对齐**：草案 `docs/handoff/REAL_MODE_INTERFACE_DRAFT_2026-10-17.md`（含待确认问题清单；不假设新字段）。
