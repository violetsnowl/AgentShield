# 三模式数据流重构与验收（2026-10-17 · feature/research-risk-contracts）

## 背景（用户指令要点）

- 三个**互相独立**的模式选项卡，全局贯穿 01/02/03 三页：**抽取检验 ｜ 研究情景 ｜ 真实Agent**。
- 未执行对应测试时，第二、三页**不得**提前展示预设风险测算与保费；严禁「未运行抽取检验却显示 ¥31,746 / ¥25,641 / ¥35,866.88」。
- 删除第一页底部技术折叠区（C 独立核验 / A 研究理算 / 查看核验与理算详情）；只删 UI，不删原始证据、C 核验结果与 A 保险计算。
- 尽量复用现有代码；不修改 B/C/A 算法与原始数据；不重跑 100 条规则基线；不调用 DeepSeek；不改保费公式；不伪造核验/赔款。

## 实现（提交 `71f7d84`）

- `frontend/src/routing.ts`：`ModeId = sampling | scenario | agent`（sampling 为默认、不入 URL；scenario/agent 显式入 URL）。
- `frontend/src/App.tsx`：
  - 新增 `ModeTabs`（第一页顶部）与 `ScenarioIntro`（研究情景第一页固定介绍，全部取自既有配置）。
  - 数据源按模式隔离：抽取检验=当前规则基线批次（`bscale-web-rule-baseline-*`，含恢复）；真实Agent=`agentBatch`（仅「本次见证完成」或「用户明确选择」时设置）；研究情景=固定情景 JSON。
  - 空状态：抽取检验未运行 → 「尚未执行抽取检验」（第二、三页均无任何数字）；真实Agent 未选择 → 「尚无真实Agent测试结果」；历史批次回看标注「历史批次」。
  - 移除 `ResultPanel`（C/A 技术面板）与「加载关联业务证据 / 重新理算」控件；「完整执行记录与核验依据」迁入页脚「开发工具」折叠内。
  - 顶部历史选择器按模式过滤（抽取检验=scripted/mock、真实Agent=observed）；研究情景模式隐藏。
  - 取消“默认落地=交付目录首个运行”的自动选择；仅 URL `run=` 深链接恢复选择。
  - `runnerConfigs.agentConfigLabel` 精简（去掉 config_id 与冻结态，保留「规则基线 / 真实模型·需付费授权」分级）。
- 金额与纪律不变式：¥31,746 / ¥25,641 / ¥35,866.88 原值未动；B 账本退款≠经济损失；核验不足一律「数据不足」。
