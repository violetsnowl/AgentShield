# Astra Codex 本轮任务 03：D 四区工作台的可运行骨架

继续在用户现有 AgentShield 仓库施工。本阶段切换到 **D 前端**，只对必要的 B 管理/只读界面适配做最小修改，不复制 B 交易业务规则、不实现 C 独立损失核验、不实现 A 的保险公式。以 V1.1 第 3、13、16、17、22、23 节和当前真实 `contracts`、`EvidenceBundle` 为准。先确认 B 两阶段能在本机启动且测试通过；若阶段 02 因 A 业务待审停留在候选，不阻塞读取开发 fixture 的前端施工。

采用 React + TypeScript + Vite，创建可启动、清晰的**单页四区工作台**：
1. **企业实验场**：可选择实际存在的开发 fixture/会话，显示售后消息、订单、商品行、当前业务状态。允许在受控开发环境创建开发会话（标为 `scripted_test` / `development_only`）；没有 C 的真实运行器时，真实“启动 Agent”显示尚未接入、不可点击，不做点击后无动作的假按钮。
2. **执行证据/资金账本**：真实请求 B 的事件分页、证据快照和账本，呈现 attempted/rejected/committed/replayed、交易ID、金额与关联 call_id；能从 333 分退款示例追溯到一笔交易与一条等价守恒账本。重放是只读展示，不能再执行退款。状态字段以真实接口为准，不发明返回值。
3. **风险/配置比较**：组件结构与数据适配器为将来的 C LossResult/正式运行清单留接口；C 未交付时，明确显示“尚未评测/待接入”，开发演示样例只能单独隔离且醒目标为 Mock，不能生成准确率、风险等级、赔款或模型优劣。
4. **合同/情景成本**：预留 A QuoteResult、合同版本/权重与证据状态的读展示结构。A 未实现时不在浏览器写第二套保费公式；“重新理算”操作禁用并解释尚待接入，不显示假商业报价。

安全与集成：**管理员令牌和模型/API 密钥不能进入浏览器、前端 bundle、截图、仓库或日志**。现有管理员 EvidenceBundle 接口需要鉴权；如要真实展示，设计一个本地受控的后端观察者桥接或其他服务端鉴权路径，限定路由、最小权限与仅本机开发，不构建无认证的 admin 代理。若无法安全接通，先完成页面与接口适配并标明阻塞，不得为了进度把 admin token 硬编码进 JS。开发前检查仓库已有前端，避免覆盖他人改动。

测试：运行真实 B 服务器与前端，手动或自动验证 2 个典型开发会话、事件排序、账本追溯、无数据/错误/加载/超时情况，以及前端构建/类型检查。确认网络断开时已保存的回放是否可用；暂不满足就明确待办，不能宣称 L1 R09 已过。

**停止点**：输出启动命令、实际页面截图路径（如可生成）、接口映射清单、证据来源标签、构建与实际联调结果，保存 `artifacts/pro_bd_sprint/03/RESULTS.md` 和 `frontend/README.md`，更新 `NEXT_STEPS.md`。不得虚构 C/A 数据，不开发高级图表和 L2，不自动执行下一阶段。
