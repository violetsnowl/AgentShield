# AgentShield V1.1：B 首轮施工与 B/C 接入底座

你是 AgentShield 项目的 B 模块实现者。本轮请直接在当前项目工作区编写、运行、测试代码，不要只输出计划或伪代码。

## 1. 阅读依据与本轮范围

先定位并阅读：
- AgentShield_v1.1_Plan.md；
- role_cards/B_Sandbox_Backend.md；
- role_cards/C_Agent_Evaluation.md；
- delivery_levels_v1.1.json；
- 工作区已有 AGENTS.md、代码、业务规则和 contracts（如存在）。

主文档优先关注第 4—7、12、14—15、17、19、23—24 节，并通读其余共同红线。文件可能位于子目录；只在项目工作区查找。缺少可选旧接口文件，就按 V1.1 新建候选接口，不假装已经读取。主文档缺失时不得声称按 V1.1 开工。

团队分工：A 负责业务规则、Gold、赔款与 B0/B1 估计；B 负责企业沙箱、账本和接口；C 负责真实 Agent、独立损失核验与批量实验；D 负责前端和交付。用户与舍友共同承担 B/D，但本轮只建设 B。

本轮目标：完成 B0 的可运行交易底座，以及 C 不导入 B 内部代码就能调用的 HTTP 接入包。仅补充交接必需的少量 B1 能力，不自动实现整个 B1、全系统 L0/L1 或前端。

不实现正式 Agent、独立损失核验、保险定价、完整实验队列、正式任务集、MCP、真实支付或公网部署。不得修改其他角色已有模块来掩盖接口问题。

## 2. 工作方式与权限

先检查工作区、Git 状态和现有运行环境，保留他人改动；不 reset、clean、强推、删除已有文件或自动上传仓库。可安全创建独立本地分支时使用 feat/b-bootstrap，否则报告当前状态，不强行切分支。

给出简短实施顺序后，按“契约候选→交易底座→HTTP 联调测试→交接”执行。普通文件命名和内部实现选择自行决定并留痕，不反复要求用户确认。涉及业务/保险含义或跨模块兼容的歧义写入待审清单；受影响部分只做明确标注的开发实现，不擅自冻结为正式规则。

仅在项目范围内创建虚拟环境、安装所需依赖和运行测试；遵守当前工具审批。不得申请关闭全部安全限制来推进。默认仅绑定 127.0.0.1；不改系统安全设置，不读无关私人目录。

本轮不调用收费模型或外部支付服务。enable_paid_runs=false、max_cost=0；不需要真实模型密钥。开发令牌本地生成，不硬编码默认管理员密码，不把令牌、密钥或 Authorization 头写入日志、截图、示例和提交。

## 3. 第一阶段：形成可执行的接口候选

以 Python + FastAPI + SQLite 为基线，优先沿用已有合理结构；保持依赖少、启动简单。选择一个权威的请求/响应模型来源，生成或一致性校验 JSON Schema、工具定义和 OpenAPI，不手工维护三套互相漂移的字段。

交付 contracts 中的工具定义、请求/响应与错误 Schema、固定 JSON 样例及可复现的导出/校验命令。七工具都要列明，但区分 implemented 与 planned；OpenAPI 如实反映当前路由，不能宣传尚不存在的接口。未实现工具不放入“当前可调用工具”清单，不返回伪成功。

尤其约定：
1. 管理端创建独立会话；管理凭据与会话凭据分离。会话令牌由管理侧安全交给运行器，绝不进入模型消息。
2. 工具 HTTP 路径、请求体、响应体、状态码和 code/message/retryable/request_id 错误结构。
3. order/item/message 等 ID 字段名、金额整数分、数量类型、状态与版本含义；工具参数禁止未声明额外字段。
4. 幂等键由客户端运行器生成；明确通过头或封套传递，不让模型自行生成运输层凭据。记录作用域、重试和查询提交状态的方式。
5. ToolEvent 的标识、序号、状态变化、交易引用与来源字段。服务端发送响应不等于客户端实际收到。
6. 管理侧只读事实导出 EvidenceBundle（本轮工程交接件）：初始/终态快照、订单商品行与分摊、已提交退款/账本、事件、版本和来源，足够让 C 对照独立 Gold 核算。不要在该包加入权威“正确答案”，Agent 令牌不得读取完整导出。
7. LossResult/QuoteResult 只沿用文档含义、列出与 A/C 对接点，不在 B 里实现或复制其算法。

将新增约定、未决问题和审核责任写入 docs/decisions/BC_contract_v0.1.md。版本初始为“候选、待 A/C/D 按职责复核”，不得代替队友签字或声称 J0 已通过。候选接口允许先做开发验证；收到队友实际意见后再冻结。

## 4. 第二阶段：实现真正有状态的最小沙箱

至少实现会话创建/状态，以及 get_case、get_order、get_business_policy、get_refund_history、submit_refund、finish_case。核心通过后可补简单 submit_human_review 工单；尚未实现时明确不可调用。

提供管理员只读事件、账本与事实导出；不以完整实验调度系统为前提。未来 evaluate/quotes 等未接入能力只说明边界，不用假结果占位。

要求：
- 使用落盘 SQLite 和可重复初始化的开发数据，不仅是进程内字典。每个 episode/会话从独立业务快照开始，重启后交易与幂等记录仍在。
- 退款由商品行、数量及冻结分摊算法在服务端计算；模型不得自由指定退款金额。多次部分退款处理整数尾差，累计金额与原实付一致。
- 验证会话/租户/订单/商品/消息归属、正整数数量、退款资格、结构化确认范围（存在时）、累计数量金额、原渠道及期望版本。不能靠删除正常控制制造事故。
- 交易、账本、订单更新、关键提交事件和幂等请求状态原子提交。JSONL 是可恢复导出，不作为唯一的事务事实来源。
- 通过身份和作用域检查后，同键同参已成功请求应返回原交易；不能因为第一次退款改变了订单版本，就把原请求重试误报为 STALE_STATE。同键不同参报冲突；新键旧版本拒绝；换键仍受累计限制。
- 明确 finish_case 后的新写入规则；结束任务不删除或改写交易，历史查询与合法幂等结果恢复仍可用。
- 核心测试可用少量开发 fixture；优先使用 A/D 已提供规则。缺失时只构造公开事实充分的开发样例，标 development_only/待业务复核，不当成 A/D 已审定的 12 个 L0 或正式 24+4 任务。
- 不读取正式 holdout/Gold；不把测试 expected 数据、隐藏评分、提示词注入“正确答案”混入 Agent 可见内容。B 只输出事实，不计算 Agent 是否做对或真实保险损失。

## 5. 第三阶段：实际运行测试，不以生成文件代替验收

单元测试与落盘数据库集成测试必须实际执行。至少覆盖：
- 正常整单/部分退款、金额和余额守恒、分摊与尾差；
- 同键同参重试仅一笔交易，同键不同参冲突；
- 新键仍受累计上限约束，新请求旧版本拒绝；
- 越权租户/会话/订单/商品/消息被拒，Agent 不能调用管理员事实导出；
- 非法数量、额外退款金额字段和其他额外字段被拒；
- 中途异常回滚，重启后持久化与幂等结果仍在；
- 两个独立请求近同时使用同键同参时不重复入账（小规模正确性测试，不做性能工程）；
- 结束任务不篡改账本，失败请求有适当审计记录且无虚构交易；
- 提交后响应丢失的恢复。故障仅在测试层注入，注明模拟方式，不开放生产式绕过控制的开关；查询历史确认已提交，不换新键重退。

另写 scripts/bc_smoke_test.py：只使用标准 HTTP/JSON 与运行中的服务通信，不导入 sandbox 内部函数，不读数据库，不接大模型。测试驱动中的管理侧只负责建会话、核对只读证据；模拟 Agent 侧只持会话令牌调用公开工具。

该脚本要能完成“创建开发会话→查询事实与规则→退款→原键重试→查询历史→管理侧核对一笔交易”，并检查跨会话拒绝与证据一致性。输入 base_url，凭据从本地环境或安全测试配置读取，日志脱敏。

必须启动独立 HTTP 服务进程实测，不只使用进程内 TestClient。断言核对金额、交易 ID、账本条数、状态版本与结构，不只是 status_code==200。脚本标为 scripted_test/development_only，不冒充 C 的正式运行器或真实 Agent。

检查工具 Schema、服务器校验、OpenAPI 和样例的一致性。测试预期用独立固定值，不调用被测函数自己生成“正确答案”。测试失败先修实现；确属规范歧义则登记，不删测试、放宽断言或偷偷移除控制求绿。

缺权限、依赖或运行环境时，如实记录哪些没有执行。不要把未运行、跳过或环境失败写成 pass；不依赖“启动日志正常”宣布交易正确。

- docs/handoff/B_to_C.md：启动方式、认证分工、可调用工具、幂等恢复、事实导出、当前版本、待审字段、未实现功能；

如无项目级 AGENTS.md，可写简短职责边界与测试要求，引用主规范而不复制全文；已有文件保留并按最小变更更新。

最后报告：改了什么；实际运行了哪些命令和结果；现在 C 能接哪些能力；还缺什么；哪些需要 A/C/D 审核。给出可复跑操作，不只给代码截图或“完成百分比”。

本轮通过仅可称“B 首轮交易底座已自测、接口候选待消费者验收”。没有队友独立接入确认，不称 B/C 集成已验收；没有 C 的真模型及 A 的理算，不称全队 L0、J1/J2 或 L1 已完成。

完成上述目标后停在交接点，不自动扩展 L2/L3、前端、正式批次或付费调用。若中断，保留可运行检查点和 NEXT_STEPS，不用大量未测代码充当交付。
